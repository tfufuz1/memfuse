# SPEC-20260505-WP-3.2 — Encryption at Rest (AES-256-GCM)

> **Priority:** 🟡 MITTEL (Defense/Sovereign USP)  
> **Dependency:** WP-1.1 DONE (SSTable-Layer stabil)  
> **DONE-Definition:** 3 Crypto-Tests bestehen 3×. Verschlüsselte DB nicht lesbar ohne Key.  
> **Assigned:** Jules Account 10 (security)
> **Status:** ✅ DONE

---

## Ziel

Daten auf der Platte dürfen nicht im Klartext liegen.  
AES-256-GCM auf SSTable- und WAL-Block-Ebene. HKDF-SHA256 für Key-Derivation.

---

## Invarianten

1. **Vollständige AEAD**: Authentication + Encryption (keine unauthenticated encryption)
2. **Nonce-Uniqueness**: Jeder Block bekommt eine unique Nonce (monotoner Counter)
3. **Passphrase → Key** nur via HKDF (kein direktes SHA256-Hashing)
4. **Opt-in**: `LsmConfig { encryption_passphrase: None }` → Plaintext (Backward-Compat)
5. **Keine neuen unsafe-Blöcke** — aes-gcm Crate ist safe Rust

---

## Acceptance Criteria (Triple-Test)

| # | Test | Erwartung |
|---|---|---|
| AC-1 | `test_encrypt_decrypt_roundtrip` | `decrypt(encrypt(b"hello"))` == `b"hello"` |
| AC-2 | `test_wrong_key_fails` | `decrypt_block(ciphertext, wrong_key)` → `Err(...)` |
| AC-3 | `test_encrypted_db_unreadable_without_key` | SSTable-Datei, gelesen als Plaintext → kein MemFuse-Magic-Byte erkannt |
| AC-4 | `test_encrypted_db_survives_restart` | DB öffnen, schreiben, schließen, neu öffnen mit gleichem Key → Daten lesbar |

**Erlaubte Dependencies:**
- `aes-gcm = "0.10"` (AEAD, pure safe Rust)
- `hkdf = "0.12"` (KDF)
- `sha2 = "0.10"` (Hash für HKDF)
