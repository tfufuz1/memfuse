## 2. Problem Statement
The current `HnswIndex` is excellent for in-memory or hybrid usage, but for datasets exceeding 8GB RAM, we need a dedicated Out-of-Core index based on the DiskANN principles. 
Key issues to solve:
- Minimizing RAM footprint for huge datasets (100M+ vectors).
- Efficient Disk I/O via memory-mapping (`memmap2`).
- Reducing I/O latency via Beam Search and caching.
- Safe SIMD distance calculations on mmap data.

## 3. Architecture & Design

### 3.1. Index Structure
The index will follow the **Vamana Graph** design:
- A single-layer directed graph.
- Optimized for low degree (R) and high connectivity.
- Stored as a flat file with a header, followed by aligned node blocks.

### 3.2. Disk Layout
```text
[Header (64 bytes)]
  Magic: "DANN"
  Version: u16
  NodeCount: u64
  Dimension: u32
  MaxDegree: u32
  SectorSize: u32
  EntryPoint: u32
  DistanceMetric: u8
  Quantized: u8
  Q_Min, Q_Max: f32 (for SQ8)
[Padding to SectorSize]
[Node Block 0]
  Vector: [f32; Dimension] or [u8; Dimension]
  NeighborCount: u32
  Neighbors: [u32; MaxDegree]
  DocId: u64
  Padding to SectorSize
...
[Node Block N]
```

### 3.3. Out-of-Core Strategy
- **Mmap-backed Storage:** Use `memmap2` to map the entire index file.
- **Node Caching:** An `AHashMap`-based cache with a configurable memory budget.
- **Beam Search:** A search algorithm that explores multiple paths simultaneously to reduce the number of disk random accesses.
- **Async I/O:** While mmap operations can block, we will document it and ensure heavy build/rebuild operations are handled correctly.

### 3.4. SIMD Integration
- Adapt `distance.rs` to allow safe reading from raw pointers (with alignment checks).
- SIMD distance calculations will be performed directly on the mmap'd vector data to avoid copies.

## 4. Technical Requirements & Invariants

### 4.1. Sovereign Core Invariants
- **INV-DISKANN-1 (Zero-Panic):** All errors during build/load/search must be propagated via `MemFuseError`.
- **INV-DISKANN-2 (Safety):** Every `unsafe` block for mmap/SIMD must have a `// SAFETY` comment.
- **INV-DISKANN-3 (Alignment):** Node blocks must be aligned to `sector_size` (default 4096) to optimize disk I/O and potential future `O_DIRECT` usage.

### 4.2. API Contract
`DiskAnnIndex` must implement the `VectorIndex` trait from `memfuse-core`.
