## Ziel

SSTables wachsen unbegrenzt → Disk-Erschöpfung, Read-Degradation, Tombstones nie physisch gelöscht.  
Implementiere einen Background-Compaction-Daemon der SSTables ähnlicher Größe zusammenführt.

---

## Invarianten (NICHT brechbar)

1. Daten die **vor** Compaction lesbar waren, sind **nach** Compaction noch lesbar
2. Tombstones dürfen **nur** gelöscht werden wenn `seq_no < min_active_snapshot_seq`
3. Concurrent Reads während Compaction: **kein Deadlock, kein Datenverlust**
4. Atomarität: entweder vollständige Ersetzung oder keine (kein Partial State)

## Implementierungsdetail: Compaction-Algorithmus

```
1. LsmState lesen (Read-Lock): alle SSTables mit Größen
2. Größenklassen: floor(log_size_ratio(file_size)) → Gruppe
3. Gruppe mit >= min_sstables_per_tier Elementen → Kandidat
4. min_snapshot_seq = snapshot_registry.min_active_seq().unwrap_or(u64::MAX)
5. Multi-Way-Merge (K-Way Merge mit BinaryHeap auf (Key, SeqNo)):
   - Gleicher Key, höheres SeqNo gewinnt
   - Tombstone: skip wenn seq_no < min_snapshot_seq, sonst behalten
6. Output in Temp-File schreiben
7. Write-Lock: State atomar updaten + rename(temp, final)
8. Alte Dateien löschen (erst nach erfolgreichem State-Update)
```
