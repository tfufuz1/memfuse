> **Priority:** 🟠 HOCH

> Status: ✅ DONE

---

## Ziel

Logische Isolation mehrerer Datensätze in einer MemFuse-Instanz.  
Jede Collection hat eigenen HNSW-Index und Key-Namespace im LSM-Store.

---

## Invarianten

1. Collections sind **vollständig isoliert** — gleiche Keys in verschiedenen Collections überschreiben sich nicht
2. `drop_collection()` löscht **alle** Daten dieser Collection (Keys + HNSW-Graph)
3. Die **bestehende API** (`MemFuse::insert/search/delete`) funktioniert weiterhin unverändert (Default-Collection)
4. Collection-Namen: nur `[a-zA-Z0-9_-]`, max 64 Zeichen

---

## Acceptance Criteria (Triple-Test)

| # | Test | Invariante |
|---|---|---|
| AC-1 | `test_collections_are_isolated` | `col_a.insert("k1", v1)`, `col_b.insert("k1", v2)` → `col_a.search()` findet nur v1 |
| AC-2 | `test_drop_removes_all_data` | `col.insert(100 docs)`, `drop_collection("x")`, re-`collection("x")` → leer |
| AC-3 | `test_default_collection_compat` | `db.insert("k", v)` → `db.search()` findet "k" (keine Regression) |
| AC-4 | `test_list_collections` | 3 Collections erstellt → `list_collections()` gibt alle 3 zurück |

---

## Key-Schema

```
Default Collection:  key as-is (Backward Compat)
Named Collection:    b"__col:{name}:\x00" + key.as_bytes()
Collection Index:    b"__col_idx:\x00" + name.as_bytes() → metadata
```
