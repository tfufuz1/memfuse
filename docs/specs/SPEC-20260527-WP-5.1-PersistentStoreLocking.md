# SPEC-20260527-WP-5.1-PersistentStoreLocking

## 🎯 1. Das Ziel (Context & "Why")
Implementiert thread-safe Locking für den `PersistentCheckpointStore` (Refactoring von `CheckpointManager`), um Race-Conditions bei konkurrierenden Checkpoint-Erstellungen und Cache-Updates zu verhindern (Behebung von Audit HIGH-002).

---

## 🛡️ 2. Die Invariante(n) (The "Law")
- **[INV-CP-LOCK-1]**: Schreiboperationen (Create/Drop) müssen atomar bezüglich Storage-Interaktion und In-Memory Cache Update ausgeführt werden.
- **[INV-CP-LOCK-2]**: Der In-Memory Cache muss immer eine sortierte und konsistente Teilmenge (oder das vollständige Set) der im Storage vorhandenen Checkpoints repräsentieren.
- **[INV-CP-LOCK-3]**: Es darf kein `unwrap()` verwendet werden; alle Fehler müssen über `MemFuseError` propagiert werden.
- **[INV-CP-LOCK-4]**: Der Crate-Name `PersistentCheckpointStore` muss konsistent mit `AGENTS.md` verwendet werden.

---

## 📍 3. Speicherort & API-Signatur
- **Crate**: `memfuse-checkpoint`
- **File**: `src/lib.rs`

```rust
/// Manages persistent checkpoints and their integration with the storage engine.
pub struct PersistentCheckpointStore {
    storage: Arc<dyn StorageEngine>,
    // Nutzt parking_lot::RwLock für feinkörnige In-Memory Synchronisation
    persistent_checkpoints: parking_lot::RwLock<Vec<CheckpointMeta>>,
    registry: Arc<CheckpointRegistry>,
}
```

---

## 🛑 4. Definiertes Fehlerverhalten (Fail-Cases)
- Bei konkurrierenden Schreibzugriffen auf denselben Checkpoint-Namen muss die Konsistenz gewahrt bleiben.
- Fehler in der Storage-Engine (z.B. I/O Error) führen zu einem `MemFuseError::Internal` oder `MemFuseError::Storage`.

---

## ✅ 5. Der TDD Checkpoint (Red-Phase Vorgabe)
- **Test**: `test_concurrent_checkpoint_creation`
- **Vorgehen**: 50 parallele Tasks versuchen gleichzeitig Checkpoints zu erstellen. Einige nutzen denselben Namen, andere unterschiedliche Namen.
- **Erwartung**: Nach Abschluss aller Tasks ist der Cache konsistent mit dem Storage, keine Duplikate (außer beabsichtigt durch unterschiedliche Namen), und die Sortierung nach `seq_no` ist gewahrt.
