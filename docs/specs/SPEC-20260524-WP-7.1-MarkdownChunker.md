## Ziel

Deterministische, semantische Zerlegung von Markdown-Dokumenten in `ContextChunk`s,
basierend auf der Heading-Hierarchie. Eliminiert die Notwendigkeit externer
Chunking-Lösungen und liefert sofort verwendbare Chunks für die RAG-Pipeline.

---

## Strategischer Kontext

Memfuse positioniert sich als "SQLite für KI-Agenten" mit dem
"Markdown-as-a-Brain"-Paradigma. Markdown ist inhärent hierarchisch (H1 → H2 → Listen),
was deterministisches semantisches Chunking ermöglicht — kein Satz wird mitten im
Kontext abgeschnitten. Dies ist ein Alleinstellungsmerkmal gegenüber generischen
Token-basierten Splittern.

---

## Funktionale Anforderungen

### FR-7.1-001: Heading-basiertes Chunking

```rust
pub struct ChunkerConfig {
    /// Maximum tokens per chunk (soft limit).
    pub max_tokens: usize,           // Default: 512
    /// Minimum tokens per chunk (merge threshold).
    pub min_tokens: usize,           // Default: 50
    /// Include heading breadcrumb as metadata.
    pub include_breadcrumbs: bool,   // Default: true
    /// Heading levels to split on (1 = H1, 2 = H2, ...).
    pub split_levels: Vec<u8>,       // Default: [1, 2, 3]
}

pub struct MarkdownChunker {
    config: ChunkerConfig,
}

impl MarkdownChunker {
    /// Chunks a Markdown document into semantically coherent pieces.
    pub fn chunk(&self, markdown: &str) -> Vec<ContextChunk>;
}
```

### FR-7.1-002: Breadcrumb-Metadaten

Jeder Chunk enthält den Heading-Pfad als Metadaten:
```json
{
  "breadcrumb": "# Architektur > ## Speicherschicht > ### WAL",
  "heading_level": 3,
  "source_line": 42
}
```

### FR-7.1-003: Merge kleiner Abschnitte

Abschnitte unter `min_tokens` werden mit dem vorherigen Abschnitt verschmolzen,
solange das `max_tokens`-Limit nicht überschritten wird.

### FR-7.1-004: Token-Schätzung

Verwendet `ContextManager::estimate_tokens()` (bereits in `context.rs`).
Keine externe Tokenizer-Dependency.

---

## Invarianten

1. **Kein Chunk überschreitet `max_tokens * 1.2`** (Hard-Limit mit 20% Toleranz)
2. **Reihenfolge bleibt erhalten** — `chunks[i].source_line < chunks[i+1].source_line`
3. **Kein Content-Verlust** — `concat(chunks) == original` (modulo Whitespace-Normalisierung)
4. **Zero-Panic**: keine `.unwrap()` oder `.expect()` in Produktionscode
