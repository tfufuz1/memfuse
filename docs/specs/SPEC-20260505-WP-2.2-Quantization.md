# SPEC-20260505-WP-2.2 — Scalar Quantization (SQ8)

> **Priority:** 🟡 MITTEL  
> **Status:** ✅ DONE
> **Dependency:** WP-2.1 DONE  
> **DONE-Definition:** Recall@10 >= 95%, RAM-Reduktion >= 3×, Tests 3× grün.  
> **Assigned:** Jules Account 03 (index)

---

## Ziel

RAM-Verbrauch ~4× reduzieren: f32 (4 Bytes/Dim) → u8 (1 Byte/Dim).  
Two-Phase-Search: schnelle approximative Traversal mit u8, exaktes Reranking mit f32.

---

## Invarianten

1. **Recall@10 >= 95%** im Vergleich zur exakten f32-Suche (gemessen auf 1000 Abfragen)
2. **Keine API-Änderung** — `HnswIndex::search()` bleibt gleich, Quantization ist intern
3. Quantizer-Training: auf erstem Batch von Vektoren (lazy, beim ersten `flush()`)
4. **Optional**: `HnswConfig { quantize: bool }`. Default: `false` (Backward-Compat)


---

## Two-Phase Search

```
Phase 1 (Beam Search mit u8):
  graph_traversal(query_quantized, beam_width = k*4)
  → kandidaten: Vec<(node_id, approx_dist)>

Phase 2 (Exact Reranking mit f32):
  kandidaten.sort_by(|a,b| exact_dist(a).cmp(exact_dist(b)))
  → Top-k zurückgeben
```
