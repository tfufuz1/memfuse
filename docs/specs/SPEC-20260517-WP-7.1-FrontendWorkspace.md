# SPEC-20260517-WP-7.1-FrontendWorkspace

> **Phase:** Design & Specification
> **Doctrine:** Node.js Orchestration / React Cockpit
> **Updated:** 2026-05-17

## 1. Goal: "Das Workspace UI"
To achieve the Palantir-like conceptual endpoint, MemFuse requires a visual layer to render ontologies, agentic state-graphs, and vector similarity comparisons. Since Rust is strictly serving as the embedded "Edge-Engine" (the high-performance backend database and task runner), the presentation logic must be decoupled.

## 2. Architecture
The Workspace App will be a separate Next.js project.

### Node/Edge-Boundary Pipeline
1. **MemFuse PyO3 Bindings (WP-3.1):** Python Server exposes an ASGI/FastAPI layer interacting with `memfuse-core`.
2. **Next.js App Router API:** Consumes the internal FastAPI, proxying GraphQL/REST to the frontend.
3. **React-Flow Visualization:** Used to visually render `GraphNode` and `WorkflowEdge` rules spawned by WP-5.3.

## 3. Recommended Tech Stack
- **Framework:** Next.js (App Router)
- **State Management:** Zustand
- **Visualization:** React-Flow (for Agent workflows), D3.js (for ontology networks)
- **Styling:** TailwindCSS + Shadcn/ui
- **Transport:** tRPC or strict REST schema via OpenAPI

## 4. Development Workflow
The frontend exists in its own repository (`memfuse-studio`). It will link against MemFuse's generated FFI layers (Python/WASM) instead of compiling natively against the Rust crate workspace to maintain `memfuse-db` strict headless embedding capabilities.
